Structural Bayesian Techniques for Experimental and Behavioral Economics

22 Application: Estimating game payoffs using Quantal Response Equilibrium

While we usually know our (monetary) payoffs for sure in economic experiments because we choose them ourselves, it is common in another field that uses a lot of structural estimation to estimate them. Here, I am referring to structural industrial organization (IO), where the payoffs, or payoff parameters, to be estimated are often (say) payoffs in entry games, cost functions, and so on. While the IO people will most likely never be able to validate their estimates against their true values (because firms usually want to hide these things), as experimentalists, we can!. In particular, becuase we have set the payoffs in our game, we can work out whether or not a particular econometric technique recovers the parameters well or not.

In this chapter I will show you some logit quantal response equilibrium models where we leave some of the payoff parameters as unknown quantities to be estimated. Once we have a QRE model that works with all of the payoffs are known, this is really easy: just move the the unknown parameters from the data block to the parameters block and assign appropriate priors! Whether the model actually recovers the parameters well is, of course, a function of the data-generating process as well, and we can investigate this with simulation.

Like Holt and Palfrey (2024), we will be analyzing these data through the lens of Nash equilibrium and Quantal Response equilibrium. The Nash equilibrium is unique and in mixed strategies, which is: \[ \begin{aligned} p^\mathrm{Top}&=\frac{b-d}{b-d+c-a}\\ p^\mathrm{Left}&=\frac{c-d}{c-d+b-a} \end{aligned} \]

For Quantal Response Equilibrium, we can write the equilibrium condition as:

\[ \begin{aligned} 0&=\log (p^\mathrm{Top})-\log(1-p^\mathrm{Top})-\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U\begin{pmatrix} p^\mathrm{Left} \\ 1- p^\mathrm{Left}\end{pmatrix}\\ 0&=\log (p^\mathrm{Left})+\log(1-p^\mathrm{Left})+\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U^\top\begin{pmatrix} p^\mathrm{Top} \\ 1- p^\mathrm{Top}\end{pmatrix}\\ \text{where: }U&=\begin{bmatrix} -a & -c \\ -b & -d \end{bmatrix} \end{aligned} \]

However, as mentioned in the previous QRE chapters, it is best to not solve for QRE in mixed strategy levels. For this application I found that solving for QRE on the logit scale worked very well, and only required constant-\(\lambda\) Newton steps. So we re-write the above system as:

\[ \begin{aligned} 0&=\ell^\mathrm{Top}-\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U\begin{pmatrix} p^\mathrm{Left} \\ 1- p^\mathrm{Left}\end{pmatrix}\\ 0&=\ell^\mathrm{Left}+\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U^\top\begin{pmatrix} p^\mathrm{Top} \\ 1- p^\mathrm{Top}\end{pmatrix} \end{aligned} \]

where \(p^X=\Lambda(\ell^X)\) and \(\Lambda(y)=(1+\exp(-y))\) is the inverse logit function. So we can stack these into one function as: \[ \begin{aligned} H(\ell;\lambda)&=\begin{pmatrix} \ell^\mathrm{Top}-\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U\begin{pmatrix} p^\mathrm{Left} \\ 1- p^\mathrm{Left}\end{pmatrix} \\ \ell^\mathrm{Left}+\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U^\top\begin{pmatrix} p^\mathrm{Top} \\ 1- p^\mathrm{Top}\end{pmatrix} \end{pmatrix} \end{aligned} \]

Noting that \(\Lambda'(y)=\Lambda(y)(1-\Lambda(y))\), we can write the Jacobian of the system as:

\[ J(\ell;\lambda)=\begin{bmatrix} 1 & -\lambda \begin{pmatrix} 1 & -1\end{pmatrix}U\begin{pmatrix} 1 \\ -1\end{pmatrix}p^\mathrm{Left}(1-p^\mathrm{Left})\\ \lambda \begin{pmatrix} 1 & -1\end{pmatrix}U\begin{pmatrix} 1 \\ -1\end{pmatrix}p^\mathrm{Top}(1-p^\mathrm{Top})&1 \end{bmatrix} \]

So the Newton steps to solve for QRE at a given choice precision \(\lambda\) are just:

\[ \ell_{t+1}=\ell_t-J(\ell_t;\lambda)^{-1}H(\ell_t;\lambda) \]

Since we will be solving this a lot below, in a lot of different Stan files, I wrote a user-defined function to include in all of the programs I wrote:


  vector lpQRE(
    real lambda,
    real a, real b, real c, real d,
    data int maxiter, data real tol
  ) {
    
    /* This function solves QRE in the logit space
    */
    
    matrix[2,2] Urow = [[-a, -c],[-b,-d]];
    matrix[2,2] Ucol = -Urow';
    
    // initialization
    vector[2] logitp = [0.0,0.0]';
    
    for (ii in 1:maxiter) {
      
      vector[2] p = inv_logit(logitp);
      vector[2] p1mp = p.*(1.0-p);
      
      // zero function
      vector[2] H;
      H[1] = logitp[1]-lambda*[1.0, -1.0]*Urow*[p[2],1.0-p[2]]';
      H[2] = logitp[2]-lambda*[1.0, -1.0]*Ucol*[p[1],1.0-p[1]]';
      
      // Jacobian
      matrix[2,2] J = diag_matrix([1.0,1.0]');
      J[1, 2] += -lambda*[1.0, -1.0]*Urow*[p1mp[2],-p1mp[2]]';
      J[2, 1] += -lambda*[1.0, -1.0]*Ucol*[p1mp[1],-p1mp[1]]';
      
      vector[2] dlogitp = -J\H;
      logitp += dlogitp;
      
      if (max(abs(dlogitp))<tol) {
        break;
      }
      
      if (ii == maxiter) {
        reject("maxiter reached, lambda =",lambda);
      }
      
    }
    
    return(logitp);
    
  }

I add this to the `functions’ block for all of my Stan programs. For example, here is the program for estimating the basic logit QRE model with known payoff parameters:

  real<lower=0> lambda;
  
}

  for (tt in 1:nTreat) {
    logitp[tt] = lpQRE(
    lambda,
    A[tt],B[tt],C[tt],D[tt],
    maxiter, tol
    );

    pLeft[tt] = inv_logit(logitp[tt][2]);
  }

model {
  
  lambda ~ lognormal(prior_lambda[1], prior_lambda[2]);
  
  if (UseData==1) {

Importantly here, I have the data element `UseData’, which lets me turn on or off the likelihood contribution. This is particularly useful for doing a prior calibration, because we can use the same Stan program to get both prior and posterior simulations. Additionally, note that the data passed to Stan is in count form, collapsed by treatment. This means the sampler only has to compute QRE four times (once per treatment), rather than (say) once per played game.

22.2 Prior check

Before estimating anything, it is always worthwhile spending some time thinking about the prior. To begin with, I computed the logit QRE correspondence for a wide range of \(\lambda\), which can be seen in Figure 22.1. This is helpful because it gives you a sense of the sale of \(\lambda\): for example, we can determine what values of \(\lambda\) make similar-enough predictions to \(\lambda=0\), or Nash equilibrium (\(\lambda\to\infty\)). Here I decided that I wanted \(\lambda\approx 0.3\) to be about in the middle of the prior, so for a log-normal prior this sets the location parameter of the prior to \(\log0.3\).

But what about the scale parameter? Since the model is highly non-linear, it is not clear at first glance that setting this scale parameter to a large number is a good idea. In particular, if we pick a really large scale parameter for this prior, then almost 50% of the prior mass will be close enough to \(\lambda = 0\) (say, \(\lambda<10^{-2}\)) that participants will just be flipping fair coins, and 50% of the prior mass will be “near enough” to infinity (say, \(\lambda>1,000\)) that participants will be effectively be playing Nash equilibrium. Figure 22.2 plots posterior simulations of the logit QRE locus for the three distinct treatment for four different values of the scale parameter. The locus is the set of mixed strategies that constitute a QRE for any choice precision. Here you can see that \(\mathrm{sd}(\lambda)=1\) is probably too small, so there is not good coverage of the endpoints of the locus (both at 50-50 randomization and Nash), while \(\mathrm{sd}(\lambda)=27\) only really covers parts of the locus that are close to these endpoints. In the end, I chose \(\mathrm{sd}(\lambda)=3\) as my prior, which has reasonably good coverage of the entire logit QRE locus.

22.4 Estimation with unknown payoffs

Now we can move to the industrial organization-y task of trying to estimate the payoffs in the game. But since these payoffs were known, we can use this as a model-validation exercise to see how well our models recover the parameters. Holt and Palfrey (2024) focus on how well the model recovers the parameters \(c\) and \(d\) while knowing the values of \(a\) and \(b\). Since \(c=7\) and \(d=4\) were common to all treatments, this means estimating two additional parameters. I will do this estimation task, as well as a separate task of estimating \(a\) and \(b\), which are treatment-specific, when \(c\) and \(d\) are known. This is a harder task because there are four values of each of these parameters. Furthermore, Holt and Palfrey (2024) for this estimation assume that \(\lambda\) is fixed at \(0.70\) (their maximum likelihood estimate), whereas I will treat \(\lambda\) as a free parameter. We will have to be careful here, though, becuase we have an identification problem. For example, the model makes the same predictions if (say) we double \(\lambda\) and halve all of the payoff parameters. Therefore, it is important to keep at least one of the four payoff parameters known.

22.4.1 Unknown \(c\) and \(d\)

To begin with I follow Holt and Palfrey (2024) and estimate \(c\) and \(d\) assuming Nash equilibrium and logit QRE, however for logit QRE I allow \(\lambda\) to also be a free parameter. This basically comes down to moving a and b from the data block to the parameters block. I adopt a uniform prior over these parameters, with an upper bound of 20. 22.5.1 Hierarchical model

First, we will estimate the hierarchical model. Here, we assume that each pair has their own \(\lambda_i\), which are independent draws from the population distribution. For this, I just assumed a log-normal specification:

\[ \begin{aligned} \lambda_i&\sim \mathrm{lognormal}(\mu_\lambda, \sigma^2_\lambda) \end{aligned} \]

Importantly here while pairs are heterogeneous, they are still forced to play mixed strategies that lie on the logit QRE locus. This will be different with the equilibrium in expectation model.

Here is the code for the hierarchical model. While a lot of it looks the same as the pooled model, the big difference, other than the hierarchical specification, is that we now have to pass data at the pair level to Stan, rather than at the treatment level. Therefore there is a lot more QRE-computing to be done. Also, have a look at the generated quantities block, where I generate pTop_pop and pLeft_pop. These are the predictions of the choice probabilities for a randomly selected new subject (i.e. someone who did not participate in the experiment).


functions {
  
  
  #include input_QREsolver.stan
  
}

data {
  
  int N; // number of obsrevations (pair-treatment pairs)
  array[N] int count, top, left, pairID;
  vector[N] A, B, C, D;
  
  
  int<lower=0, upper=1> UseData;
  
  vector[2] prior_lambda_med;
  real<lower = 0> prior_lambda_sd;
  
  int<lower=1> maxiter;
  real<lower=0> tol;
  
  
  // some things to get the population averaged-predictions
  int nsim;
  vector[nsim] zsim;
  int ntreat;
  vector[ntreat] Atreat, Btreat, Ctreat, Dtreat;
  
}

transformed data {
  
  int nPairs = max(pairID);
  
}


parameters {
  
  real<lower=0> lambda_med;
  real<lower=0> lambda_sd;
  
  vector[nPairs] z; // non-centered parameterization of lambda
  
}

transformed parameters {
  
  vector[nPairs] lambda = exp(log(lambda_med)+lambda_sd*z);
  
  array[N] vector[2] logitp;
  
  vector[N] pTop, pLeft;
  
  for (tt in 1:N) {
    logitp[tt] = lpQRE(
    lambda[pairID[tt]],
    A[tt],B[tt],C[tt],D[tt],
    maxiter, tol
    );
    
    pTop[tt] = inv_logit(logitp[tt][1]);
    pLeft[tt] = inv_logit(logitp[tt][2]);
  }
  
}


model {
  
  lambda_med ~ lognormal(prior_lambda_med[1], prior_lambda_med[2]);
  lambda_sd ~ normal(0.0, prior_lambda_sd);
  
  z ~ std_normal();
  
  
  if (UseData==1) {
    for (tt in 1:N) {
    
      
      top[tt] ~ binomial_logit(count[tt], logitp[tt][1]);
      left[tt] ~ binomial_logit(count[tt], logitp[tt][2]);
    }
  }
  
  
  
}

generated quantities {
  
  vector[ntreat] pTop_pop, pLeft_pop;
  
  for (tt in 1:ntreat) {
    real a = Atreat[tt];
    real b = Btreat[tt];
    real c = Ctreat[tt];
    real d = Dtreat[tt];
    
    vector[nsim] pTop_temp;
    vector[nsim] pLeft_temp;
    
    for (ss in 1:nsim) {
      real l = exp(log(lambda_med)+zsim[ss]*lambda_sd);
      
      vector[2] lp = lpQRE(l,a,b,c,d,maxiter, tol);
      
      pTop_temp[ss] = inv_logit(lp[1]);
      pLeft_temp[ss] = inv_logit(lp[2]);
      
    }
    
    pTop_pop[tt] = mean(pTop_temp);
    pLeft_pop[tt] = mean(pLeft_temp);
    
  }
  
  
  
  
}

22.5.2 Equilibrium in expectation model

Finally, we turn to a model that does not take the logit QRE locus so seriously. This is the “equilibrium in expectation” model, which I developed for Bland (2026). Here we assume that each pair \(i\) plays mixed strategies \(\{q_i^\mathrm{Top}, q_i^\mathrm{Left}\}\), which do not have to be on the locus. But in the population, these mixed strategies are centered on the locus. That is, the model has the following hierarchical structure:

\[ \begin{aligned} q_i^\mathrm{Top}&\sim \mathrm{Beta}\left(\kappa p^\mathrm{Top}(\lambda), \kappa (1-p^\mathrm{Top}(\lambda))\right)\\ q_i^\mathrm{Left}&\sim \mathrm{Beta}\left(\kappa p^\mathrm{Left}(\lambda), \kappa (1-p^\mathrm{Left}(\lambda))\right) \end{aligned} \]

That is, \(\kappa>0\) is the new parameter, which measures the concentration of mixed strategies around the point on the QRE locus. We can therefore use this to measure how closely participants are playing to the logit QRE locs. Here I use the Beta distribution (rather than, say logit-normal or probit-normal), because the Beta preserves the expectation, as in \(E[q_i^X\mid \lambda]=p^X\). Hence the name of the model.

Here is the Stan program for estimating the equilibrium in expectation model.


functions {
  
  
  #include input_QREsolver.stan
  
}

data {
  
  int N; // number of obsrevations (pair-treatment pairs)
  array[N] int count, top, left, pairID;
  vector[N] A, B, C, D;
  
  
  int<lower=0, upper=1> UseData;
  
  vector[2] prior_lambda;
  real<lower=0> prior_kappa;
  
  int<lower=1> maxiter;
  real<lower=0> tol;
  
  
  // some things to get the population averaged-predictions
  int nsim;
  vector[nsim] zsim;
  int ntreat;
  vector[ntreat] Atreat, Btreat, Ctreat, Dtreat;
  
}

transformed data {
  
  int nPairs = max(pairID);
  
}


parameters {
  
  real<lower=0> lambda;
  
  real<lower=0> kappa;
  
  vector<lower=0, upper=1>[N] pTop_g, pLeft_g;
  
  
}



transformed parameters {
  
  array[N] vector[2] logitp;
  
  vector[N] pTop, pLeft;
  
  for (tt in 1:N) {
    logitp[tt] = lpQRE(
    lambda,
    A[tt],B[tt],C[tt],D[tt],
    maxiter, tol
    );
    
    pTop[tt] = inv_logit(logitp[tt][1]);
    pLeft[tt] = inv_logit(logitp[tt][2]);
  }
  
}


model {
  
  lambda ~ lognormal(prior_lambda[1], prior_lambda[2]);
  kappa ~ normal(0.0, prior_kappa);
  
  
  pTop_g ~ beta(kappa*pTop, kappa*(1.0-pTop));
  pLeft_g ~ beta(kappa*pLeft, kappa*(1.0-pLeft));
  
  if (UseData==1) {
    
    top ~ binomial(count, pTop_g);
    left ~ binomial(count, pLeft_g);
    
  }
  
  
  
}

generated quantities {
  
  vector[ntreat] pTop_pop, pLeft_pop;
  
  for (tt in 1:ntreat) {
    real a = Atreat[tt];
    real b = Btreat[tt];
    real c = Ctreat[tt];
    real d = Dtreat[tt];
    
    vector[nsim] pTop_temp;
    vector[nsim] pLeft_temp;
    
    for (ss in 1:nsim) {
      
      vector[2] lp = lpQRE(lambda,a,b,c,d,maxiter, tol);
      
      pTop_temp[ss] = inv_logit(lp[1]);
      pLeft_temp[ss] = inv_logit(lp[2]);
      
    }
    
    pTop_pop[tt] = mean(pTop_temp);
    pLeft_pop[tt] = mean(pLeft_temp);
    
  }
  
  
  
  
}

To finish with, how can we interpret the new parameter \(\kappa\), which measures concentration around the QRE locus? This is particularly difficult because \(\kappa\to\infty\) corresponds to all play being exactly on the locus. To try to answer this, I note that the standard deviation of the Beta distribution is greatest when its mean is \(0.5\), in which case it becomes:

\[ \frac{0.5}{\sqrt{\kappa+1}} \]

so let’s work with this quantity. Figure 22.13 shows the posterior and prior distributions of this quantity, with the posterior shown with the solid curve. Here we can see that there is substantial updating between the prior and posterior, and that most of the posterior mass is around \(0.15\). For a variable that is bounded between zero and one, this is quite a substantial value. Therefore we can conclude that off-equilibrium play at the pair level is substantial.
